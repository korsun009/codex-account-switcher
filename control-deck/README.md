# Codex Control Deck 1.0.0

Codex Control Deck — отдельный нативный WinUI 3-пульт для Windows 10/11. Он использует существующий локальный Codex Remote API и не заменяет Codex Account Switcher, Telegram-бот или навык Алисы.

## Возможности

- **Пульт**: статус ПК, Codex и VPN, аккаунты, все именованные окна лимитов и встроенные команды.
- **Сценарии**: понятная форма для запуска программы, сайта, `.ps1`-файла или расширенной PowerShell-команды.
- **Подключения**: адрес Windows API, скрытое чтение токена из переменной среды, ручная синхронизация и результат проверки.
- **Telegram и Алиса**: удалённо разрешённые сценарии появляются автоматически, без копирования пути или команды на сервер.

## Подключение

1. Запустите Windows API через задачу `CodexStartRemoteApi` с `Run with highest privileges`.
2. Сохраните bearer token в пользовательской переменной `CODEX_REMOTE_API_TOKEN`.
3. Откройте **Подключения**, укажите локальный URL API, например `http://127.0.0.1:8765/`, и нажмите **Синхронизировать**.
4. Не публикуйте этот HTTP-порт в интернет. Telegram и Алиса должны идти через доверенный домашний gateway и защищённый туннель.

Токен не показывается и не сохраняется в `actions.json`. Интерфейс хранит только несекретные настройки подключения.

## Создание сценария

1. Откройте **Сценарии** и задайте короткий латинский ID, русское название и описание.
2. Выберите тип действия и укажите файл, URL или команду через соответствующее поле.
3. Добавьте голосовые фразы Алисы по одной на строку, через запятую или точку с запятой.
4. Нажмите **Проверить локально**.
5. Для Telegram и Алисы включите **Разрешить удалённый запуск**, оставьте обязательное подтверждение и подтвердите предупреждение о риске.
6. Сохраните сценарий. Бот и webhook загружают список заново при следующем запросе.

Удалённый API возвращает только ID, название, описание, фразы и признак подтверждения. Полный путь, аргументы, `.ps1` и текст PowerShell-команды остаются на Windows ПК.

## Данные и восстановление

Сценарии хранятся у текущего Windows-пользователя:

```text
%APPDATA%\CodexControlDeck\actions.json
%APPDATA%\CodexControlDeck\actions.last-good.json
```

Запись атомарная. При повреждении основного JSON приложение пытается загрузить последнюю корректную копию. Обновление и удаление установщика не удаляют эти файлы.

## Установка

Готовые автономные установщики лежат отдельно по архитектурам:

```text
artifacts\installers\win-x64\Codex-Control-Deck-1.0.0.exe
artifacts\installers\win-x86\Codex-Control-Deck-1.0.0.exe
```

Оба EXE содержат MSI и все .NET/Windows App SDK зависимости, создают ярлыки и регистрируют удаление в Windows. Сборки не подписаны Authenticode, потому что доверенный сертификат code signing не настроен; перед установкой проверяйте `artifacts\checksums\SHA256SUMS.txt`.

## Сборка

```powershell
dotnet test .\control-deck\CodexControlDeck.Tests\CodexControlDeck.Tests.csproj -c Release
pwsh -File .\control-deck\installer\build-installers.ps1
```

Скрипт публикует self-contained `win-x64` и `win-x86`, проверяет обязательные `.xbf`/`.pri`, строит и валидирует MSI, затем создаёт автономные WiX Burn EXE.
